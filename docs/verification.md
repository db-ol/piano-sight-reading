# 验证记录

日期：２０２６年１０月２５日。以下结果针对本地实现，尚未发布到 GitHub Pages。

## 已完成

### 单元测试

运行 `node --test tests/*.test.js`，５８项全部通过。完整输出见 [unit-results.txt](../artifacts/unit-results.txt)。

- 生成器核对１６个调、５种拍号和３档难度，主要参数循环覆盖２８８０首曲子。另检查１９２０首的持续音重叠，避免双手同音或交叉。核对每小节时值、音名与调号、音域、合法时值、每手最多双音、弱起与末小节互补、终止式、长音落在和弦音上、全部力度及合法休止。
- 对齐使用合成音符数据，覆盖全对、和弦内错一个音、漏音、多音、漏起音、匀速变慢、局部拖拍、中途停顿、迟起、首尾缺失、重复乐句、低置信与完全无关演奏。另覆盖４８０份正确生成曲演奏和２４０份单音错误演奏。
- 音频恢复使用模拟 AudioContext，检查页面隐藏、pagehide、页面恢复、系统中断、时钟停走及 resume 未完成后，首次点击重建上下文。
- 输入测试核查 WAV、重采样、混合声道、MIDI 重复按键与和弦、准备音排除、三分钟采集上限，以及取消后的迟到权限、并发结束、MIDI 断开、模型下载取消、音频会话用途切换和资源释放。
- 真实运行本地模型两次，输入三秒合成 C4、E4、G4 和弦。三个目标起音都被识别，但也出现额外音和长音分段。两次推理结束后的模型张量数均为２４５。此测试证明模型可执行和该路径的临时张量回收，不能证明钢琴识别准确率或长期内存稳定。

## 尚未完成的真机验证

以下项目没有在真实 iPhone、原声钢琴、电钢琴或物理 MIDI 连接上完成，不能写成“已通过”。

1. iPhone Safari 麦克风授权、拒绝后恢复和实际输入设置。
2. 手机锁屏、切后台、电话或 Siri 中断后，首次点击是否真正发声。
3. 示范播放后立刻录音、录音后再次播放，以及内置扬声器、耳机和蓝牙之间的路由与音量。
4. 真实双手与和弦、弱音、踏板、混响、环境噪声下的转录准确性。
5. 不同 iPhone 的模型冷启动耗时、三分钟录音的内存峰值和长时间稳定性。
6. 电钢琴实际 USB 或蓝牙 MIDI 连接、事件延迟和设备断开。
7. GitHub Pages 子路径上发布后的安装、缓存更新和离线启动。当前只验证 localhost 上的同源静态服务。

因此，网站把麦克风分析标为实验功能，提供回听、自评和不确定性提示，不给出虚假的准确率或官方分数。模拟输入能验证逻辑，不能替代上述真机项目。

## 真机试用建议

发布后先用一首简单题试用。听示范，锁屏再回来点击示范。录一遍单音和一遍双手，回听确认收音正常。再比较屏幕上的疑似标记与实际弹奏。最后缓存识别模型，断网重开，检查读谱、播放和分析。出现问题时记录 iPhone 型号、iOS 版本、钢琴类型、耳机情况及具体步骤，便于复现。
